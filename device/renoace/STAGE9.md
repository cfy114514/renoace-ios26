## 这次适配的范围

ADT `/arm-io/ranges` 使用与本机 `/soc` 一致的完整身份转换，按 Apple 树的 LE 64位格式编码 `<0,0,0xffffffff>`，地址和长度单元均为2。没有为了让时钟检查通过而伪造非零 GIC 总线基址。

该 XNU 分支把数值为0的 SoC 基址误当作“属性不可用”，提前跳过识别和时钟解析。本实验对已独立校验的身份树使用一处私有 RAM NOP 原型修正这一可用性判断，原文件不变；后续必须在源码中区分“查询失败”和“合法物理基址0”，并审查后续中断/串口消费者。该原型不是完整平台修复。

早期 C 会原样建立17,129条 static-if 链接，并修改10个已定位的文本指令。模型按确切允许范围核对，不再错误地断言执行后内核所有字节不变。桥在 C 首条栈指令前保存全部32个 Q 寄存器及 FPCR/FPSR，重放原指令继续 C；返回时恢复并再次记录 Q/FP 状态。原始 `arm_init` 栈帧和 PE 返回后的寄存器契约分别验证。

P06 有39处私有内核指令补丁、3条桥内恢复分支。为保留完整64KiB探针栈，Image 的尾前缀比 P04 增加一页4KiB：Image `0x3911000`，DTB缓冲偏移 `0x3811000`。当前 ABL 指令审计和两个条件装载窗口重新核对，余量为 `0x306000` / `0x2d06000`。

## 验证与恢复

MAX/A72 原生 MMU 完整模型各8/8、独立 SIMD 桥四例、190项实际内存原语、独立集成审查、当前 CPIO/DTB/ADT/源码身份和19个打包拒绝条件均通过。模型只映射物理RAM，不以 API 伪造高虚拟别名；时间进度和显式注入故障仍属于模拟输入。完整模型额外以32个不同 Q 寄存器和非零 FP 控制值核对恢复，不能用本轮手机初始值代替全部特性测试。

记录取回后已恢复原 recovery 并读回 SHA `8c951baaceed969b29877bc9090d5872ecad0df4cb0e13c2c27c111f5c8ae009`，boot/dtbo/vbmeta 哈希未变。经原 TWRP 的重启命令回到正常 YAAP，`boot_completed=1`，诊断 FDT 属性和暂存目录不存在。

成功构建和精确源码冻结在 `out/xnu-c-init-probe-attempt1/`，128个文件共283,309,083字节，各文件复制前、目标与复制后源哈希一致。下一阶段继续推进 `arm_vm_init` 和新的映射/返回边界；本阶段不构成完整 XNU 或 iOS 开机证明。
